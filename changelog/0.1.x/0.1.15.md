# 0.1.15 — 2026-08-18

## Added

- **`who_query_indicator_data` gains offset-based pagination and deterministic ordering** — new `offset` and `sort` (`year_desc` default, `year_asc`) inputs; rows are ordered `TimeDim [desc|asc],SpatialDim,Dim1,Id` so a capped result is the top of a defined slice rather than an arbitrary sample, and offset paging can't repeat or skip rows across page boundaries. Response adds `offset`, `hasMore`, `pageInfo`, `nextOffset` ([#8](https://github.com/cyanheads/who-gho-mcp-server/issues/8), [#13](https://github.com/cyanheads/who-gho-mcp-server/issues/13)).
- **`who_search_indicators` gains offset-based pagination** — new `offset` input threads into the existing catalog `$skip` call; response adds `offset`, `hasMore`, `pageInfo`, `nextOffset` ([#10](https://github.com/cyanheads/who-gho-mcp-server/issues/10)).
- **`.github/` community-health files** — `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `SECURITY.md`, `FUNDING.yml` — and `.gitattributes`.

## Changed

- **`@cyanheads/mcp-ts-core`** ^0.10.9 → ^0.11.5.
- **Catalog queries (`who_list_indicators`, `who_search_indicators`) now send `$orderby=IndicatorCode`** so `$skip`-based offset paging is ordered by contract rather than by unspecified upstream behavior.
- **`bunfig.toml`** — adds `minimumReleaseAge` (3-day supply-chain hold on fresh publishes, excluding `@cyanheads/mcp-ts-core`) and the Socket security scanner (`@socketsecurity/bun-security-scanner`).
- **Dockerfile** — BuildKit cache mounts on `bun install`/`bun add`, `--ignore-scripts` on the dependency-install stage, `--omit=peer` on the production install to drop the framework's optional peer tiers.
- **Skills synced from framework** — `add-test`, `add-tool`, `api-auth`, `api-canvas`, `api-config`, `api-context`, `api-linter`, `api-testing`, `api-utils`, `api-workers`, `code-simplifier`, `design-mcp-server`, `field-test`, `git-wrapup`, `orchestrations` (+ its workflow files), `polish-docs-meta`, `release-and-publish`, `security-pass`, `setup`, `techniques`, `tool-defs-analysis`.

## Fixed

- **`who_query_indicator_data` rejects `year_from > year_to`** as a validation error (`invalid_year_range`) instead of querying upstream and returning the misleading generic `no_data` reason ([#9](https://github.com/cyanheads/who-gho-mcp-server/issues/9)).
- **`GhoService.queryData()` no longer exhausts its retry budget on deterministic upstream rejections** — an OData query the GHO API rejects for malformed input now throws with `retryable: false` and a new `invalid_query` error reason, instead of `withRetry` burning all 3 retries on a failure that can't succeed on retry. Non-2xx responses across the service now route through the framework's `httpErrorFromResponse` (5xx retryable, 4xx fail-fast) instead of a single blanket `serviceUnavailable` for every status ([#12](https://github.com/cyanheads/who-gho-mcp-server/issues/12)).
