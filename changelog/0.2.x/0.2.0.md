# 0.2.0 — 2026-08-18

## Added

- **`who_list_dimension_values` gains `limit`, `offset`, and `parent_code` inputs** — deterministic `Code`-ordered paging (default limit 100, max 500) and hierarchical narrowing (e.g. `dimension: "COUNTRY"`, `parent_code: "EUR"` for the 58 countries in the WHO European Region). Response adds `totalCount`, `offset`, `hasMore`, `pageInfo`, `nextOffset` (#14).
- **Three `who://dimension/{dimensionCode}/values` resource templates** — the bare default page, an explicit `{?limit,offset}` page, and a `{?limit,offset,parentCode}` page narrowed to one parent. Registered separately because the MCP SDK's RFC 6570 matcher compiles query variables as required and order-sensitive, so one template with optional variables can't serve all three shapes (#14).
- **`dimensionsNote` field** on `who_get_indicator_metadata` and `who://indicator/{indicatorCode}/metadata`, present when `dimensions` is empty — points callers at a sample `who_query_indicator_data` row's `dim1Type`/`dim2Type` to recover the indicator's actual dimensions (#11).

## Changed

- **Breaking: `who_list_dimension_values` and the bare `who://dimension/{dimensionCode}/values` resource now cap at 500 values per call (default 100)** — both previously returned every value unbounded. `GHO` (3,103 values) and `DHSMICSGEOREGION` (4,932) exceed the cap, so full single-call retrieval is no longer possible for either; callers must page with `offset`. Smaller dimensions (`COUNTRY` 234, `AGEGROUP` 163, and the rest) still fit in one call at `limit: 500`.
- **`GhoService.listDimensionValues()` sends `$orderby=Code`** on every request — `Code` is unique across every dimension checked, giving offset paging a stable total order (#14).
- **Empty-result semantics split three ways** on `who_list_dimension_values` and its resources: an unfiltered empty result still means the dimension doesn't exist (`dimension_not_found`); a `parent_code` matching nothing returns an empty page with a `notice` explaining the filter matched zero rows; an `offset` at or beyond `totalCount` returns an empty page noting the last reachable offset (#14).
- **`who_query_indicator_data`'s `region_codes` description** names `parent_code` in place of the nonexistent `parentCode` filter it previously pointed callers at (#14).
- **README** corrects the `COUNTRY` dimension's size from 194 to 234 entries and documents `GHO`/`DHSMICSGEOREGION` paging.

## Fixed

- **`who_get_indicator_metadata` / `who://indicator/{indicatorCode}/metadata` no longer report valid indicators as not found.** Codes resolving in the `Indicator` catalog with no rows in `IndicatorDimension` — roughly 1,300 of 3,089 catalog indicators, many still carrying queryable data — return `dimensions: []` plus `dimensionsNote` instead of `notFound`/`all_not_found` (#11).
