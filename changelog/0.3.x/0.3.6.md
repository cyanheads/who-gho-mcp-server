# 0.3.6 — 2026-10-09

## Changed

- **`@cyanheads/mcp-ts-core` ^0.13.6 → ^0.13.14.** Tool errors now end their text with `(reason <reason> · request <id>)` and carry `data.requestId`, the ID the server's log records for that call carry (framework 0.13.10). A numeric string for a number field (`limit: "5"`), a lone string for a list field (`country_codes: "JPN"` → `["JPN"]`), and `null` at an optional field (dropped, so its default applies) are now repaired before validation instead of rejected (framework 0.13.14). `ctx.log` notifications sent to the client honor `MCP_LOG_LEVEL` and mask sensitive fields (framework 0.13.11).
- **MCP SDK `@modelcontextprotocol/server` 2.0.0 → 2.3.1** through the framework. On stdio, closing stdin now aborts requests still in flight instead of answering them, and an HTTP JSON-RPC batch of more than 100 messages is refused (framework 0.13.9).
- **Tool definitions no longer forward their declared recovery hints by hand.** The framework fills `data.recovery.hint` from each tool's `errors[]` (framework 0.13.10), so the hints callers receive are unchanged.
- **Docker image:** production dependencies install in a `deps` stage on the build platform and cross-install for the target architecture, so multi-arch builds no longer run Bun under emulation (framework 0.13.10). OpenTelemetry packages install at the framework's declared peer ranges through `scripts/install-otel.ts`, behind the release-age gate and the Socket scanner (framework 0.13.8, 0.13.10). Musl-only native bindings are pruned (framework 0.13.11), the base image moves to Bun 1.4.2 (framework 0.13.7), and the unused `MCP_FORCE_CONSOLE_LOGGING` variable is removed (framework 0.13.8).
- **`.env.example` and the README document the framework's opt-in operator settings:** `OTEL_EXPORTER_OTLP_ENDPOINT` as a base endpoint for traces and metrics (framework 0.13.7), and failed-call payload logging via `LOG_TOOL_FAILURE_PAYLOADS` (framework 0.13.8). `.env.example` also gains the OTLP per-signal endpoints, `MCP_REQUEST_STATE_KEY`, and the log rate-limit settings (`MCP_LOG_RATE_LIMIT_THRESHOLD`, `MCP_LOG_RATE_LIMIT_WINDOW_MS`).
- **Packaging:** the `.mcpb` bundle is kept out of the npm tarball (`!dist/*.mcpb`); the bundle excludes `/.cache/`, `/coverage/`, `/tests/`, `/docs/idea.md`, and `/logs/`; `.gitignore` ignores every `.env*` file except the example templates; and `.dockerignore` also excludes the MCP Registry token files.
- **The CodeQL workflow runs one analysis job per language.** Framework skills, the framework scripts behind `devcheck`, `lint:mcp`, `lint:packaging`, and `release:github`, and the agent protocol in `CLAUDE.md`/`AGENTS.md` are synced to 0.13.14. A `start` script is added.

## Fixed

- **The MCP Registry `streamable-http` package entry now sets `MCP_TRANSPORT_TYPE=http`.** It used to pass `run start:http` arguments, which the package binary ignores, so a registry client launching that entry got the default stdio transport. Both npm entries now declare `runtimeHint: "npx"` (framework 0.13.11 scaffold fix).
