# 0.3.0 — 2026-08-18

## Changed

- **Breaking: `who_query_indicator_data`'s output field `spatialLabel` is renamed to `parentLocation`, and a new `parentLocationCode` field is added.** `spatialLabel` never held a label for the row's own spatial dimension — it held the row's *parent* WHO region (a `JPN` row carried `spatialLabel: "Western Pacific"`). A consumer reading it for a country name never had one, and still doesn't: upstream carries no name for a row's own spatial entity. Both fields are omitted (not `null`) on rows whose spatial dimension is itself a region or aggregate, e.g. `spatialDim: "EUR"` or `"WB_HI"` (#15).
- `ParentLocationCode` is now requested in the upstream `$select`, and `format()` renders the parent region as its own labelled segment (`— parent: Western Pacific (WPR)`) instead of folding it into the slash-joined spatial group (#15).

## Fixed

- **`queryData()` now classifies non-2xx responses it previously missed.** Only `getJson()` checked `response.ok`; `queryData()` special-cased `status === 404` and otherwise fell through to body parsing, so a non-JSON 4xx retried as a transient failure instead of failing fast. The new check runs *after* the OData-envelope branch — every malformed-query class GHO serves returns HTTP 400 with a diagnostic envelope, and checking status first would discard GHO's own error message in favor of a generic HTTP 400. Both request paths now share one `httpError()` classification method (#16).
